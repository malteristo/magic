# On Shared Context

*Memory is context over time. A shared git is shared context when the writers do not share a disk.*

**Status:** Practice lore — earned 2026-09-06  
**Kin:** `on_form_and_function.md` (state appreciates), `on_the_braid.md` (the repository as witness), `on_the_unenforced_declaration.md` (a claim needs a check)

---

## The finding

Intelligence is not the bottleneck. Access is. A later agent cannot use what it cannot see.

When several agents share a filesystem, they already share context: they write files, they read files. Git adds almost nothing except a chronicle.

When they do **not** share a filesystem — two machines, two people, two Spirits — the smallest surface that both already know how to read is a git repository with a brief at the root. No new product. No new vocabulary. Commit when something is the record the other side should attune to.

That is the primitive. Circle and Portal were early names for the two directions of it (offer / subscribe). They are optional labels, not a second architecture.

## Chat is transport

A Discord eddy and a Cursor session are the same kind of thing: the raw conversation is ground truth. The harvest (eddy note, briefing, picture, memory page) is what a later turn attunes to. The repo is where a harvest that must outlive one machine is signed.

Do not treat git as a flight recorder. The flight recorder already exists — the transcript. A commit is a judgment: *this is now the record*. Commit-every-turn makes the repo noisier and harder to attune to, which is the opposite of why the repo exists.

| Layer | What it is | Who writes |
|---|---|---|
| Transcript | Ground truth. The session as it happened. | The substrate (Discord, Cursor, Claude Code) |
| Harvest | Memory: notes, topics, pictures, briefings | Memory / River / Spirit, on a rhythm |
| Shared git | Harvest (or a brief + signed artifacts) that another disk must see | A writer who means it |

## Rhythm

Agents write files when they already would — checkpoint, dissolve, stale rebuild, release. Git happens when a writer and a reader do not share a filesystem, and the file is signed enough to attune to.

A shared git **earns itself** at that test. It is not created in advance of a second reader.

## What this retires as required method

The neuron model, Spirit Transmission Protocol, required `founding/` trees, synthesis rhythms, and pull-trigger seneschals. Those were method. A shared repo is a git repo. Register it if you want Spirit to remember it exists. Offer and subscribe remain useful words.

## Ground truth on the Forge

The Cursor session history is the Forge's eddy transcript. It is personal chronicle, never a public surface. Keep it on the practitioner's always-on machine, in their personal git. Craft memory from it the way eddy notes are crafted from Discord — harvest, not a second firehose.

The same is true of Claude Code histories (the Anvil) and of any later substrate that keeps a conversation log.

## What turtleOS Is

**turtleOS is infrastructure for a persistent practice partner** — Discord-native runtime, local/cloud LLM routing, file-based practice root, continuity surfaces. **The product is the infrastructure, not a being.** Default attunement is **native** (`character/soul.md` under the practice root).

It does **not** "ship from the Magic development environment" as Magic's software twin. Magic is one practice that may run *on* the platform; Forge is where this Mage develops both Magic and the platform checkout.

| Layer | What | Where law lives |
|-------|------|-----------------|
| **Platform (shell)** | `discord_bot.py`, river/eddies, models-by-role, launchd | `TURTLE_SPEC.md` |
| **Practice files** | character, flows, story, boom, state under practice root | Spec § practice-root layout; instance config |
| **Magic workshop** | summoning, lore, desk/floor/box, intentions | Forge only (`~/Documents/magic/`) |

## What Survives from the Old Scroll

- **Files as the practice surface** — no mandatory cloud DB for practitioner state; sovereignty of data on the machine that holds the practice root.
- **Depth scales with model capability** — same architecture, different cognitive quality.
- **Agent-relevant scaffolding** — persistent orientation (compass/intentions), capture/curate (boom/bright), continuity across sessions — useful beyond human practitioners; still not "Magic = IDE / tOS = software."

# Flow: Model

**Purpose:** Make a model change an *occasion* with a procedure, so the practice improves with each generation by measurement rather than by feel
**Invocation:** `. model` (arrival scope, first session on a new model) · `@model` (mid-session, when the substrate reports a model Spirit has not run before)
**Reads:** `desk/craft/model_probes.md` (probe set, sealed answers, run log) · `desk/craft/practice_falsifiers.md` (the ledger) · `library/resonance/foundations/lore/model_profiles/<vendor>.md`

> Method-pile instructions teach a model how to think; capable models make them redundant, and the redundant ones stay because nothing measures them. This flow is the measurement. Evaluation proposal item B, sanctioned 2026-09-03.

---

## When it runs

The substrate names a model Spirit has no run log for — a new family, a new major version, or a new substrate on the same model. Not for routine sessions. Arrival on `. model` does the ordinary arrival *plus* Part 1; Parts 2–3 span the next sessions and close at their releases.

---

## Part 1 — Cold probes (first arrival, ~10 minutes)

The probes test whether the **read path** works on this model: can a Spirit that did the ordinary arrival reads answer questions about the record without being pointed at the file?

1. Do the ordinary arrival reads for the scope. Nothing extra.
2. Open `desk/craft/model_probes.md` and read **only** `## Probes` — not `## Sealed answers`. Answer each in one line, from what is already in context or a read Spirit would ordinarily make. Write the answers down before scrolling.
3. Read `## Sealed answers`. Score each probe: **hit** (matches, cited or citable) · **near** (right file, wrong detail) · **miss**. Record the run in `## Run log`: date, model, substrate, score, misses by number.
4. A **miss is a read-path finding, not a prose finding.** The fix is in what the arrival reads (item D — generated views, never `bright.md` or the backlog file in full), never a new sentence telling the model to remember. If the same probe misses on two model generations, the record is structured wrong for retrieval: name that.

The sealed answers were drafted by Spirit from the record and confirmed by the Mage (decision 2026-09-03). Each cites its source so confirmation is a pointer check, not a re-read. New probes: add when a session shows a retrieval failure that a probe would have caught; retire when a probe has hit on three generations running.

---

## Part 2 — Falsifier run (next three sessions)

Every `live` row in the ledger names what a recurrence looks like. For three ordinary sessions on the new model:

- At each release, the **Calibration** field records the model and `Falsifiers fired: F-xx, F-yy` (or `none observed`). Spirit checks the arrival surface, the plan, the questions asked and the commit path against the rows it can observe from inside the session: word cap (F-14), queue-first (F-03), acted-not-reported (F-04), off-list asks (F-69), altitude (F-37, F-64), private lane (F-34, F-48), state.md regenerated (F-32), export ran (F-28).
- The Mage marks anything he noticed that Spirit did not: a fired row is his call as much as Spirit's.

After three sessions, rows that **never fired** are retirement candidates; rows that fired stay `live` and gain a model in their column — the first time the ledger will know which model does what.

---

## Part 3 — Re-ablation (sessions four to six)

For each retirement candidate, in one batch:

1. Remove the one-line rule from the flow file. The ledger row stays, status `ablated YYYY-MM-DD`.
2. Run three more ordinary sessions with the same Calibration discipline.
3. A row whose falsifier **fires** with the rule gone → restore the line, row back to `live`, incident column gains the new date and model. A row that stays quiet → `retired`; the line stays out.

Batch size is the whole candidate set. Ablating one rule at a time across dozens of sessions is how the previous ablations stayed at N=2 for six weeks (`floor/research/ablation_01_over_asking.md`).

---

## Close

Append to the vendor profile under a dated heading: model, substrate, probe score, rows fired, rows retired, one sentence on what this generation stopped needing. The profile's *observed layer* is the practice's actual model-behaviour record; the pulls listed above it are hypotheses until a run confirms them.

*A rule the current model does not need is not wisdom kept; it is attention spent. The ledger keeps the wisdom — the flow keeps only what still earns its place.*
